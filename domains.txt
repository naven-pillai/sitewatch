# sitewatch domain list — one entry per line, # for comments
#
# Bare domains get https:// added. Full URLs work too.
# Options after the entry:
#   expect="text"  body must contain this string
#   noseo          skip robots.txt and sitemap checks
#   nowww          skip the www/apex twin check
#   nordap         skip the domain registration lookup
#   slow=3000      raise the "slow" threshold, in ms

# One row per site, pointed at /api/health rather than at the homepage.
#
# The health route runs a real Postgres read and returns 503 when it fails, so
# it catches what a homepage check structurally cannot: a CDN will serve a
# cached 200 homepage straight through a total database outage.
#
# robots, sitemap, www-twin and domain-registration are deliberately left ON.
# They read the *host*, not the path, so one row covers them. Splitting each
# site across a homepage row and a health row bought nothing and cost a second
# certificate read, which is how the report came to show 40 days and 89 days
# for the same agencies.asia certificate in the same snapshot.
#
# The tradeoff, accepted knowingly: /api/health is a different route from the
# homepage and can stay green while the homepage 500s. Nothing here will catch
# that.
#
# slow=3000 because a route invoked once every 30 minutes is always a cold
# start, and the boot is most of the number: measured from sin1, these answer
# in 126-461 ms warm but 173-1620 ms cold. 3000 clears the worst honest cold
# start with room to spare while still noticing a real regression. It was 6000
# while latency came from a US runner, where the Pacific crossing alone put
# every row near the line.

https://kerja-ai.com/api/health             slow=3000 expect='"status":"ok"'
https://agencies.asia/api/health            slow=3000 expect='"status":"ok"'
https://businessai.my/api/health            slow=3000 expect='"status":"ok"'
https://magnesmarketing.com/api/health      slow=3000 expect='"status":"ok"'
https://navenpillai.com/api/health          slow=3000 expect='"status":"ok"'
